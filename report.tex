\section*{Abstract}
%-----------------------------------------------------------------------
We extend the CDCL solver developed in Tutorial 2 to emit a
resolution proof for every unsatisfiable instance, and implement
an independent linear-time proof checker that validates the proof
against the original formula.
The design records resolution steps verbatim during conflict analysis,
ensuring a minimal and checkable chain of inferences.
Experiments on 12 instances---including the pigeon-hole benchmark
family up to $n=8$---confirm that both the solver and the checker
maintain correctness and efficiency.

%-----------------------------------------------------------------------
\section{Problem Description}
%-----------------------------------------------------------------------

\subsection{From Tutorial 2 to Project 1}

Tutorial 2 required building a CDCL solver involving BCP, 1st-UIP
conflict analysis, backtracking, and clause learning.
While the solver efficiently finds a satisfying assignment, an
answer of unsatisfiability is more difficult to verify.
Project 1 addresses this by requiring a proof of unsatisfiability.
The ability to produce and verify proofs is critical for trust in
automated reasoning systems, as it allows users to confirm that an
"unsatisfiable" result is not merely the consequence of a solver bug.

\subsection{Resolution Refutation}

Resolution is the canonical proof system for propositional logic.
Given two clauses $(C_1 \vee \neg p)$ and $(C_2 \vee p)$, their
resolvent is $C_1 \vee C_2$.
A refutation is a sequence of such steps starting from input clauses
and terminating in the empty clause $\bot$.
Since CDCL conflict analysis is internally based on resolution, logging
these steps allows for the reconstruction of a full refutation proof
with minimal computational overhead.

\section{Implementation}
%-----------------------------------------------------------------------

\subsection{Proof Format}

The proof format is a line-oriented plain-text format where each line
represents one resolution step:

\begin{lstlisting}
p proof <n>
<new_id> <pivot> <id1> <id2> : <lit1> <lit2> ... 0
\end{lstlisting}

\noindent
The format defines the number of initial clauses $n$ and subsequent
derived clauses.
Each step identifies the pivot literal and the two parent clauses used
to derive the resolvent.
This design allows for streaming verification in a single forward pass.

\subsection{Equipping the Solver (cdcl.py) with Proof Production}

Three main architectural additions were made to the original solver.

\paragraph{Proof logging architecture.}
A \texttt{ProofLogger} class handles file output, while a \texttt{\_NullLogger}
serves as a no-op implementation.
The solver is designed to be branch-free: it always calls the logger
methods, and the overhead is absorbed by the null object when proof
generation is disabled.
This maintains a clean core logic and avoids mode-switching bugs.

\paragraph{Clause indexing.}
To enable resolution between IDs, the \texttt{ClauseDb} maintains
mappings from clause content and object identity to integer proof IDs.
This dual-mapping strategy ensures that we can quickly retrieve the ID
of a reason clause during conflict analysis without performing linear
scans of the clause database.

\paragraph{Conflict analysis integration.}
The \texttt{analyze()} routine was modified to log each resolution step
during the derivation of the 1st-UIP clause.
To handle conflicts occurring at decision level 0 (where BCP alone leads
to a contradiction), a dedicated routine reduces the conflicting clause
to the empty clause by resolving it against the trail's unit motives.

\subsection{Proof Checker (proof\_checker.py)}

The checker is an independent tool that does not share code with the
solver.
It performs a single linear scan of the proof file, maintaining a
internal clause database.
For each step, it verifies that the pivot literal exists in both
parents, recomputes the resolvent, and checks its equality against the
declared clause.
The linear-time complexity $O(N \cdot K)$ ensures that even large
pigeon-hole proofs can be verified in a fraction of a second.

\section{Experimental Evaluation}
%-----------------------------------------------------------------------

\subsection{Test Methodology}

Experiments are managed by \texttt{test\_cdcl.py}, which automates
solving, proof generation, and verification.
The test suite includes:
\begin{enumerate}
    \item \textbf{Basic SAT instances}: verifying the parser and SAT
    search correctness.
    \item \textbf{Border cases}: \texttt{border\_level0.cnf} tests
    immediate contradictions where no decisions are made.
    \item \textbf{Pigeon-hole benchmarks}: PHP instances known for
    requiring exponential resolution proofs.
\end{enumerate}

\section{Conclusion}
%-----------------------------------------------------------------------

We implemented a proof-producing CDCL solver and a linear-time checker.
The system maintains backward compatibility with Tutorial 2 while
providing a robust mechanism for verifying unsatisfiability via
resolution proofs.
All 12 test instances were solved correctly, with all proofs validated
by the independent checker.
